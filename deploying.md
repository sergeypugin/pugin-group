# Как деплоить сайт?

Предположим, что у Вас есть уже готовая связка `HTML + CSS + JavaScript`. Хостинг сайта можно осуществить при помощи следующих сервисов:

| Сервис                                            | Цена в месяц (в руб.) | Особенность                                                                                               | Для чего                   |
| ------------------------------------------------- | --------------------- | --------------------------------------------------------------------------------------------------------- | -------------------------- |
| [Yandex Cloud](https://yandex.cloud/ru)           | <5                    | Очень дёшево (оплата за место/трафик), сервера в РФ, но сложнее в настройке                               | Коммерческие сайты в РФ    |
| [GitHub Pages](https://pages.github.com/)         | 0 (Бесплатно)         | Настройка в пару кликов и авто-SSL, но обязательно публичная репа, риски блокировки в РФ и уже функционал | Пет-проекты                |
| [beget.com/hosting](https://beget.com/ru/hosting) | 420 или более         | Дорого, но фиксированная цена. Простейший интерфейс                                                       | Огромные сайты для бизнеса |

Купить домен можно много где, но самый дешёвый и, как мне показалось, надёжный способ - это через [beget.com/domains](https://beget.com/ru/domains) со следующими ценами:
- 199 руб. за регистрацию домена (т.е. создать домен и продлить на год)
- 420 руб. за продление уже существующего домена на год

Ниже описано, как опубликовать сайт с выбором [Yandex Cloud](https://yandex.cloud/ru) для хостинга и [beget.com/domains](https://beget.com/ru/domains) для получения кастомного домена:
1. [yandex cloud хостинг](#yandex-cloud-хостинг)
2. [Подключение кастомного домена в Yandex Cloud](#подключение-кастомного-домена-в-Yandex-Cloud)

# Yandex Cloud хостинг

## Создание пустого бакета
1. Перейдите на https://console.yandex.cloud
2. Нажмите на кнопку меню слева-сверху (подсветится топик "Все сервисы")
3. Выберите `Инфраструктура и сеть -> Object Storage`.
4. Вам предложат создать первый бакет. Нажмите на `Создать бакет`.
5. Теперь у Вас открылось окно с настройками бакета. Выберите:
	1. **Имя бакета**: просто имя, что тут ещё сказать. Если вы будете создавать сайт с кастомным доменом, важно назвать бакет как сайт (т.е. для сайта `https://example.com` бакет должен называться `example.com`).
	2. **Макс. размер**: достаточно 2 Гб только ради того, чтобы вдруг не случился глюк/взлом или что-либо ещё, из-за чего с Вас бы взяли куда больше за хранение содержимого бакета
	3. **Класс хранилища**: выберите `Стандартное`, т.к. другие будут в той или иной степени нацелены на то, чтобы хранить файлы дёшево, но цены на обращение к ним будут огромными
	4. **Доступ**: т.к. сайт должен быть виден всем, а его настройки - дело уже ваше личное, то переведите тумблеры в такие состояния:

		| Настройка              | Тумблер |
		| ---------------------- | ------- |
		| Чтение объектов        | `Для всех`   |
		| Чтение списка объектов | `Для всех`   |
		| Чтение настроек        | `С авторизацией`  |

	1. **Версионирование**: оставьте выключенным, на это есть гитхаб, который в отличие от здешнего метода не хранит каждую версию просто как копию, а помнит `diff`.
	2. Нажмите `Создать бакет`
	3. Создайте платёжный аккаунт и готово!


## Хостинг

После создания бакета откроется список всех ваших бакетов. Если что, в эту вкладку можно попасть всё так же через кнопку меню слева-сверху (подсветится топик "Все сервисы"), выбрав `Инфраструктура и сеть -> Object Storage`.

Нажмите на название вашего бакета. После перехода на страничку бакета нажмите в левом меню на `Настройки`, а затем в верхнем меню на `Веб-сайт` и выберите `Хостинг`. Выберите, какой файл будет главной страницей, а какой - страницей для ошибок. Скопируйте ссылку на будущий сайт.

## Пополнение бакета репозиторием с GitHub

### Получение ключа доступа для GitHub

Перейдите в меню и выберите `Управление ресурсами -> Identity and Access Management`. Нажмите `Создать сервисный аккаунт`.

Далее придумайте любое имя (например, `github-deployer`), выберите роль `editor` внутри списка `storage` (или просто впишите `storage.editor`) и нажмите на `Создать`.

ВАЖНО: не путайте роли `editor` и `storage.editor`. Нужна вторая, у неё меньше прав, только нужные нам.

Теперь, когда вы создали сервисный аккаунт, нажмите на имя этого аккаунта. В верхнем меню справа нажмите на `Создать новый ключ -> Создать статический ключ доступа` и кликните на `Создать`. Вы получите связку id + key.

>[!important]
>Значение ключа будет вам доступно только 1 раз, в момент создания. После закрытия окна со связкой id + key, ключ больше увидеть не получится! Так что сохраните себе его куда-то, далее мы запишем его в секреты репозитория с вашим сайтом, после чего он возможно уже вам не понадобится.

### Сохранение ключей доступа в репозитории

Перейдите в свою репу в GitHub. Перейдите по пути `Settings -> Secrets and variables -> Actions`. Кликните на `New repository secret`.  Вам потребуется сейчас создать три секрета.

| Name             | Secret                 |
| ---------------- | ---------------------- |
| YC_SA_ACCESS_KEY | id                     |
| YC_SA_SECRET_KEY | key                    |
| YC_BUCKET_NAME   | Название вашего бакета |
>[!important]
>После создания секрета его содержимое не будет доступно. Так что будьте осторожны.

### Наполнение бакета репозиторием

Создайте в корне репозитория по пути `.github/workflows` файл `deploy.yml` со следующим содержимым:

```yml
name: Deploy to Yandex Cloud Object Storage

on:
  push:
    branches:
      - main

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Скачивание кода из репозитория
        uses: actions/checkout@v4

      - name: Загрузка файлов в Яндекс Облако
        uses: jakejarvis/s3-sync-action@master
        with:
          args: --acl public-read --follow-symlinks --delete --cache-control 'no-cache, must-revalidate' --exclude '*.md' --exclude '.git*' --exclude '.git*/*' --exclude '.obsidian*/*'
        env:
          AWS_S3_BUCKET: ${{ secrets.YC_BUCKET_NAME }}
          AWS_ACCESS_KEY_ID: ${{ secrets.YC_SA_ACCESS_KEY }}
          AWS_SECRET_ACCESS_KEY: ${{ secrets.YC_SA_SECRET_KEY }}
          AWS_S3_ENDPOINT: 'https://storage.yandexcloud.net'
          AWS_REGION: 'ru-central1'
```

>[!note]
> Браузер всегда старается хэшировать все возможные файлы, так что при обновлении сайта возможна ситуация, когда не все файлы были обновлены. На этот случай в коде есть строка `--cache-control 'no-cache, must-revalidate'`, которая "приказывает" браузеру убедиться, что версия файла - последняя.

Тут из всего, что вам может понадобиться редактировать - это строка с `--exclude` (выбрать файлы/папки, которые не передавать в облако с гитхаба). Правила просты:
1. Чтобы убрать файл, введите `--exclude 'file_name'`
2. Чтобы убрать папку со всем её содержимым, введите `--exclude 'folder_name'`

Разберём вариант выше

| Часть строки               | Описание (для чего)                          | Цель (что убрать)              |
| -------------------------- | -------------------------------------------- | ------------------------------ |
| `--exclude '*.md'`         | Убрать все `md`-файлы                        | `README` и пр.                 |
| `--exclude '.git*'`        | Убрать все файлы, начинающиеся с `.git`      | `.gitignore`, `.gitattributes` |
| `--exclude '.git*/*'`      | Убрать все папки, начинающиеся с `.git`      | `.git`, `.github`              |
| `--exclude '.obsidian*/*'` | Убрать все папки, начинающиеся с `.obsidian` | `.obsidian`                    |

>[!important]
>Ни в коем случае не используйте `"` вместо `'`. GitHub в случае с `"` разворачивает регулярки во всё то, что найдёт (т.е. вместо `--exclude "*.md"` он отправит в Yandex Cloud `--exclude README.md SomeFile.md AnotherFile.md`), что сломает деплоинг.

Теперь стоит вам закоммитить этот файл, как тут же по ссылке `https://{your-bucket-name}.website.yandexcloud.net` откроется ваш сайт!

# Подключение кастомного домена в Yandex Cloud

Перейдите на [beget.com/domains](https://beget.com/ru/domains). Проверьте, что ваш домен не занят, и если он свободен, то купите его. Потребуется подтвердить личность (удобно через ГосУслуги) и оплатить регистрацию домена - 199 руб. Напомню, что через год цена уже изменится - 420 руб.

Теперь вернитесь в [Yandex Cloud](https://console.yandex.cloud) и перейдите по `Инфраструктура и сеть -> Cloud DNS`. Далее:
1. Нажмите на `Создать зону`.
2. Введите название зоны и придумайте имя (для сайта `https://example.com` обязательно вводите в название зоны именно `example.com.` с точкой на конце, а вот имя пусть будет просто `example-zone`)
3. Выберите тип `Публичная` и нажмите `Создать`

Вы создали зону. Теперь в списке зон нажмите на название той зоны, которую создали. Далее:
1. В правом верхнем углу нажмите на `Создать запись`
2. Выберите тип `ANAME`
3. Вставьте значение `{bucket-name}.website.yandexcloud.net.`
4. `TTL` можете изменить, но очень рекомендуется оставить значение 600 (в секундах, что равно 10 минутам), чтобы и кэш работал как подобает, и ваши обновления сайта долго не ждать.

Теперь перейдите на [управление DNS на beget.com](https://cp.beget.com/dns) и кликните под доменом на `Редактирование DNS-серверов`. Откроется панель с 4-мя DNS. В первые два впишите `ns1.yandexcloud.net` и `ns2.yandexcloud.net`, а в 3-м и 4-м удалите содержимое, пусть поля станут пустыми. Нажмите на `Сохранить`.

Теперь, чтобы браузер смог открыть сайт по защищенному протоколу `https://`, осталось лишь привязать SSL-сертификат. Для этого вернитесь в [Yandex Cloud](https://console.yandex.cloud) и перейдите по `Безопасность -> Certificate Manager`. Далее:
1. Кликните на `Добавить сертификат` и выберите `Сертификат от Let's Encrypt`.
2. Придумайте имя. Пусть для `example.com` будет `example-cert`.
3. Вставьте ваш домен (для `https://example.com` это будет `example.com`) и кликните на `Создать`

Вы создали сертификат. Кликните на него и вы увидите статус `Validating`.  Загорится зелёным `Issued` он не сразу, понадобится несколько часов (у меня потребовалось +-3).

>[!note]
>Этот шаг был не самым понятным для меня, но нужно во время оставления заявки посмотреть логи и скорее всего надо создать CNAME-запись. Это делается в пару кликов и там ничего особенного указывать не нужно. Однако после этого шага процесс зависнет ещё на пару часов.
>
>Все подробности валидации сертификата вы всегда можете найти в логах.

Теперь осталось лишь подключить этот сертификат:
1. Перейдите в `Инфраструктура и сеть -> Object Storage`
2. Кликните на ваш бакет для сайта, выберите в меню слева `Безопасность` и теперь в меню сверху `HTTPS`.
3. Нажмите на `Настроить`
4. В появившемся разделе выберите свой новоиспечённый сертификат и нажмите `Сохранить`

Осталось скрестить пальцы, вспомнить про `TTL = 600` и вернуться на свой сайт через 10 минут. И на этом весь этот тяжёлый, местами запутанный, но тем не менее желанный деплоинг закончен.
